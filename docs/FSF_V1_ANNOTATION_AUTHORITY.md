# FSF v1 Annotation Authority and Provenance Contract

## 1. Scope

This document fixes the source authority and provenance contract for all
annotation-dependent, real-data FSF v1 products. It governs annotation joins,
representative-feature tables, enrichment inputs, biological summaries,
figures, tables, and manuscript products. It does not change the FSF v1
scientific definition or authorize regeneration of any downstream product.

The governing scientific lock is `docs/FSF_V1_CURRENT_SCIENTIFIC_LOCK.md`,
SHA-256:

`0c7a1462d210144c726041952cb4dfd7a59b386a7136d161090fa443d1d3b9d1`

`current_fsf_feature_metrics.tsv LEFT JOIN FSF_v1_annotation_master.tsv BY feature_id`

- Joined rows: 91,122.

- Duplicate composite keys: 0.

The FSF columns must be copied directly from the mathematical authority. The
35 non-key annotation columns must be appended from the biological annotation

`readr::read_tsv()` -> `dplyr::left_join(by = "feature_id")` -> `readr::write_tsv()`

An audited readr implementation reproduced the documented serialization
derivative exactly. This does not establish which readr version was installed

Raw `eggnog_evalue` differences were fully reproduced by R double parsing and

The raw master and historical atlas are not asserted to be identical. The

## 10. Large-File Storage and Distribution Policy

The 203,946,583-byte annotation master is not committed as a normal Git blob
because of its size. The 1,235,282,601-byte historical atlas is not imported.

Every future use of the external annotation master must verify its SHA-256
before analysis. A matching local path without a matching hash is insufficient.
No downstream workflow may silently substitute a similarly named file.

A later publication or release phase may distribute the master through an
appropriate data archive or release asset. This contract establishes no DOI,
archive record, or release location.

## 11. Downstream Usage Rules

Downstream workflows may join annotations, select subsets, summarize, create
gene sets, perform enrichment, and plot results. They must:

- Verify the annotation-master SHA-256 before reading it.
- Join annotation by `feature_id` only after confirming key uniqueness.
- Preserve the current `condition` plus `feature_id` identity key.
- Preserve all authoritative FSF values without recalculation or rounding.
- Reject row multiplication, row loss, or unmatched current identities.
- Exclude all historical FSF-derived fields.
- Record both source hashes in generated-product provenance.

## 12. Authority Order

For annotation-dependent current real-data products, authority is:

1. `docs/FSF_V1_CURRENT_SCIENTIFIC_LOCK.md` for scientific definitions.
2. `results/current_fsf_v1/current_fsf_feature_metrics.tsv` for all real-data
   FSF mathematical and classification fields.
3. `FSF_v1_annotation_master.tsv`, identified by its locked SHA-256 and
   schema, for biological annotation fields.
4. The four underlying annotation resources for generation provenance.
5. `FSF_condition_class_annotation_master.tsv` only as historical provenance.

No lower-ranked source may override or recompute a field governed by a
higher-ranked authority.
